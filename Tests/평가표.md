## 11월 15일 Room 연동 인계

11월 14일 준비 기준으로 팀 서버 커밋 0423529의 Common/protocol.h를 게임 클라이언트와 GameWorld 양쪽에 적용했다. 서버 테스트 18건이 통과했고 SceneManager.cpp와 StageScene.cpp가 공용 헤더로 컴파일됐다.

팀장 연동 순서

1. 서버 프로젝트에 Server/GameWorld.cpp를 컴파일 대상으로 추가하고 각 방이 별도의 GameWorld를 소유하게 한다.
2. 게임 시작 시 선택한 MAP_ID로 InitBoard를 호출하고 해당 방의 직전 갱신 시각을 시작 시각으로 설정한다.
3. 게임 중인 방에서 현재 시각과 직전 시각의 차이(ms)를 Advance에 전달하고 직전 시각을 갱신한다. 두 번째 인수는 이동 한 스텝을 실행할 함수다. 물풍선 StepBomb는 Advance 내부에서 호출한다.
4. 통합 확인 시 대기 중인 방의 이동 호출은 0회, 게임 시작 후 300ms 동안 이동은 25회, 물풍선은 6회여야 한다. 두 방의 시작 시각을 다르게 해서 각 방의 누적 시간이 독립적인지도 확인한다.

실제 Room을 거치는 항목의 판정은 머지 후 팀장 검증 예정이다.

설치 표시는 원본 Bomb::Render의 스프라이트 규격을 재사용한다. 애니메이션 시각은 GetTickCount64를 사용한다.
통합 시 완성된 S2C_Attack을 SceneManager::OnAttack에 전달한다.
서버 방 업데이트는 GameWorld::Advance(room, elapsedMs, stepMovement)를 호출해야 폭발 시 해당 방의 Broadcast가 실행된다.
통합된 브랜치의 NetworkManager → GameClient → SceneManager 경로에 맵·설치 패킷 처리를 연결했다. 게임 시작 패킷에서 씬 전환을 예약하여 같은 Poll에서 뒤이어 도착한 맵을 보관할 수 있다. 동일 씬 전환을 다시 예약해도 보관된 맵을 유지한다. 실제 네트워크 화면 검증은 아직 수행하지 않았다.
클라이언트의 폭발 표시 및 설치 물풍선 제거는 11월 20일 S2C_Explode 처리 일정이다.

통합 코드 재검증에서 서버 32건 통과 및 StageScene, SceneManager, GameClient, NetworkManager 소스 컴파일 성공을 확인했다. Room 구현은 들어왔으나 방별 GameWorld 소유·게임 시작 초기화·공격 요청 전달·Update 호출 연결은 팀장 인계 작업으로 남아 있다.

### 원본 코드와 연결 방법

- ServerBomb::Covers는 Client/CrazyArcade/Bomb.cpp의 Covers 십자 범위 검사를 옮겼다. hitMask는 같은 파일의 TryHit처럼 같은 폭발에서 피해자당 한 번만 맞게 한다.
- HitPlayer::invincibleTicks는 Player.cpp의 kHitBlinkMs=500을 서버 물풍선 주기 50ms로 나눈 10틱이다. 클라이언트 깜빡임 처리는 26일 담당 작업이다.
- Room은 참가자의 세션 ID, 현재 행/열, 생존 상태를 유지하는 HitPlayer[4]를 준비하고 `world.Advance(room, elapsedMs, stepMovement, players, applyHit)`를 호출해야 한다. players는 매 틱 새로 만들지 말고 무적 틱을 유지하며, 새 게임/슬롯 교체 때 초기화한다.
- applyHit는 팀원 담당의 사과/하트/시간 차감 및 탈락 규칙 연결 지점이다. 콜백에서 생존 상태가 바뀌면 같은 players 배열에도 반영한다. 피격 판정은 물풍선 갱신 직후 50ms마다 실행된다.
- 기존 Advance 오버로드는 호환성을 위해 남겨두었고 피격은 새 오버로드를 호출해야 실행된다. 현재 작업 브랜치에는 Room의 GameWorld 갱신 연결이 없어 운영 서버까지 연결 완료한 상태가 아니다. dev/팀원 브랜치는 병합하지 않았다.
- 온라인 개인전의 물줄기는 설치자도 피격 대상으로 포함한다. 원본 2인 모드의 GetOpponent로 한 명만 고르는 부분 대신 살아 있는 참가자를 순회한다.
- S2C_ItemGet는 서버의 최종 수치를 덮어쓰므로 클라이언트에서 능력치를 다시 증가시키지 않는다. 도시 시계 시간/HUD는 담당 팀원의 S2C_StageState로 반영한다.
